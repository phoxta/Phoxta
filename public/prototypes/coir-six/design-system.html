Coir Six — foundations, components and patterns for learning products

Everything on this page is derived from the Coir Six dashboard. Use the tokens as the single source of truth, compose screens from the components, and follow the patterns so new features feel native to the product on day one.

Principles

Four rules that explain why Coir Six looks the way it does. When a decision isn't covered below, fall back to these.

01 · Calm surface, one loud colour

Backgrounds are near-white and desaturated. Brand purple is reserved for the primary action, the current selection, progress, and the hero. If everything is purple, nothing is.

02 · Soft geometry

Large radii (16–24px) on containers, pills on controls, circles for avatars and icon buttons. Nothing has a sharp corner; friendliness is structural, not decorative.

03 · Hierarchy through weight, not size

A narrow type scale (11–30px) with SemiBold for anything scannable and Regular for supporting copy. Colour (ink → muted → caption) does the rest.

04 · Category colour is semantic

Blue = Front End, Purple = UI/UX, Pink = Branding, Mint = success, Peach = warmth/people, Orange = destructive. A colour always means the same thing.

Responsive rules

BreakpointBehaviour
≥ 1400Fixed 1352px shell centred on backdrop, 24px radius, app shadow.
769 – 1400Shell scales proportionally (0.9 → 0.68). No reflow — the composition is the product.
≤ 768Native-app mode: sidebar → bottom tab bar, header → app bar, grids → snap rails, tables → stacked rows, right panel → stacked cards. 20px gutters (16px under 400px).
Touch targets. Every tappable element is ≥ 44 × 44 on mobile, including the 32px Follow button (extend the hit area with padding, not by enlarging the visual).

Usage & tokens

Two companion files ship with this guide: coir-six-tokens.json (for Figma Tokens / Style Dictionary) and coir-six-tokens.css (drop into any web project). Import the CSS and every component here works by class name.

<link rel="stylesheet" href="coir-six-tokens.css">

.my-card { background: var(--color-surface-card); border-radius: var(--radius-xl); padding: var(--space-4); }
.my-cta  { background: var(--color-text-primary); color: var(--color-text-on-brand); border-radius: var(--radius-pill); height: var(--size-control-lg); }
.my-tag  { background: var(--color-accent-blue-soft); color: var(--color-accent-blue); font-size: var(--type-tag-size); }

Naming convention

category / role / modifier — e.g. color/brand/primary-soft, type/body-sm, radius/xl. Roles describe purpose, never appearance, so a rebrand only touches the values.
