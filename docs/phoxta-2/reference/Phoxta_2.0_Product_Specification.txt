Executive Product Definition


Phoxta 2.0 is a multi-tenant opportunity discovery and venture creation application. Its core
object is an Opportunity. Users discover or create opportunities, investigate them with sourced
research, define assumptions, run validation experiments, shape a business model, build
operating assets and prepare a launch. A separate Ready-to-Launch catalogue packages selected
opportunities into developed businesses.

 PRIMARY PRODUCT PROMISE
 Discover business opportunities. Understand what must be true. Build the ones worth pursuing.


Product outcomes

 Outcome                                                     Definition of success

 Discovery                                      A user can find or create an opportunity relevant to their goals
                                                     and constraints.

 Understanding                                          The user can distinguish evidence, inference and unknowns.

 Validation                                                              Critical assumptions are explicit and linked to experiments and
                                                                 evidence.

 Decision                                               The user can proceed, revise, pause or stop with a traceable
                                                                      rationale.

 Execution                                      A promising opportunity can become an offer, MVP, operating
                                                        workflow and launch plan.

 Learning                                      New market/customer evidence updates the opportunity rather
                                                           than living in disconnected notes.


Non-goals for initial release
 Predicting business success or generating success probabilities.
 Automating legal, financial or regulatory decisions without human review.
 Building every possible business type end-to-end in v1.
 Replacing specialist market-data providers; Phoxta should orchestrate sources and preserve provenance.
 Allowing autonomous agents to publish, purchase, message customers or alter production systems without
    explicit permissions.

4. Opportunity Engine - End-to-End User Flows


4.1 Flow A: User has no idea
 1. Complete lightweight onboarding.
 2. Select Explore for me.
 3. System retrieves/generates candidate opportunities from curated library + fresh signals + profile constraints.
 4. Ranking service scores fit dimensions separately and creates explanation text.
 5. User sees cards with thesis, customer, why-now, evidence strength and biggest uncertainty.
 6. Save keeps it in Saved; Investigate clones/links it into a private workspace.
 7. Workspace creates initial Opportunity Brief and top assumptions.
 8. System recommends one next action: review evidence, clarify customer or create first experiment.

4.2 Flow B: User has an idea
 1. User describes idea in natural language.
 2. Intake agent extracts proposed customer, problem, solution, geography and model; missing fields remain
   unknown.
 3. Research planner creates questions rather than immediately endorsing the idea.
 4. Research pipeline gathers external evidence and alternatives.
 5. Synthesis agent rewrites the input as an Opportunity Thesis.
 6. Assumption agent generates critical assumptions.

                                                Phoxta 2.0 Product Specification

--- PAGE 8 ---
 7. User reviews/edits and accepts the workspace.
 8. System recommends validation based on highest importance/uncertainty assumptions.

4.3 Flow C: Start from problem
 1. Capture who has the problem, context, frequency, current workaround and consequences.
 2. Search for corroborating evidence and existing alternatives.
 3. Generate multiple solution-independent opportunity directions.
 4. User selects one direction or keeps the problem as an exploration.
 5. Create Opportunity Brief with problem evidence separated from proposed solution.

4.4 Flow D: Industry map
 1. Select industry + geography.
 2. Research planner decomposes value chain, customer groups, workflows and constraints.
 3. Signal extractor identifies recurring pain, regulatory changes, technology shifts and underserved segments.
 4. Clustering service groups related signals into opportunity territories.
 5. User drills into a territory, then a specific opportunity.
 6. Investigate creates workspace.

4.5 Flow E: Decision review
 1. User opens Decisions.
 2. System summarises evidence added since previous review.
 3. Assumptions grouped as supported, contradicted, unknown or changed.
 4. System highlights unresolved critical risks and next cheapest tests.
 5. User chooses Proceed, Revise, Pause or Stop and writes/accepts rationale.
 6. Snapshot is stored immutably; current opportunity state updates.

9.1 Agent execution contract
 Every agent receives a typed JSON input schema and must return typed JSON.
 Every factual claim emitted from research carries evidence_ids; unsupported synthesis is marked
   hypothesis.
 Tool permissions are allowlisted per agent.
 Cost/time budgets are set per job and plan.
 Long jobs run asynchronously via queue/worker; UI shows progress states.
 Human approval is mandatory before publishing public content, finalising a decision review on behalf of a
    user, or activating external-action workflows.

10. Discovery and Research Pipeline


 1. Trigger: user request, editorial research request, scheduled signal refresh, or stale-data refresh.
 2. Plan: convert intent into research questions, geography, time window, source classes and stop conditions.
 3. Retrieve: query approved search/news/public-data/provider APIs.
 4. Canonicalise: normalise URLs/entities; deduplicate by canonical URL/content hash.
 5. Extract: chunk content; capture claims, dates, metrics, entities and short supporting excerpts.
 6. Evaluate: source relevance, recency, geographic fit, primary/secondary status and contradictions.
 7. Store: source metadata + atomic evidence; do not store more copyrighted text than operationally necessary.
 8. Synthesize: generate opportunity/market artifact using evidence IDs.
 9. Quality gate: detect unsupported claims, stale evidence, conflicting metrics and missing geography/time
   period.
 10. Human/user review: present what is known/inferred/unknown.
 11. Refresh: schedule or trigger re-research when evidence becomes stale or the user changes market/customer
   assumptions.
